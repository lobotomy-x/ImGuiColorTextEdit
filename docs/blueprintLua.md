# BlueprintLua: a UEVR Lua scripting backend for BlueprintEditor

`BlueprintLua` (`BlueprintLua.h` / `BlueprintLua.cpp`) turns
[BlueprintEditor](blueprintEditor.md) graphs into ready-to-run Lua scripts for
[UEVR](https://uevr.io), the Unreal Engine VR injector. You wire up nodes the
way you would in Unreal's Blueprint editor and get a `.lua` file you can drop
into your UEVR profile's `scripts` folder.

```cpp
#include "BlueprintEditor.h"
#include "BlueprintLua.h"

BlueprintEditor blueprint;
blueprint.SetBlueprint("my_script", "UEVR");
BlueprintLua::SetupUEVRRegistry(blueprint);

// ... build or edit the graph ...

std::string lua = BlueprintLua::GenerateScript(blueprint);
```

## The UEVR registry

`SetupUEVRRegistry` fills the editor's reflection registry with the UEVR Lua
scripting surface:

| Palette group | Contents |
| --- | --- |
| Add Event | `Pre/Post Engine Tick`, `Pre Slate Draw Window`, `XInput Get State`, `Draw UI`, `Script Reset` — each becomes a `uevr.sdk.callbacks.on_*` registration |
| UEVR\|API | `Find UObject`, `Get Local Pawn`, `Get Player Controller`, `Get Engine`, `Execute Command`, `Print`, `Log Info` (the `uevr.api` object) |
| UEVR\|VR | controller/HMD indices, `Trigger Haptic Vibration`, mod values, standing origin, `Recenter View` (the `uevr.params.vr` object) |
| UEVR\|XInput | `Is Button Pressed`, triggers and thumbstick axes for the `XINPUT_STATE` passed to the XInput event |
| UObject | `Get/Set Property`, `Call (No Args)` / `Call (1 Arg)`, `Get Class`, `Is A`, `Is Valid`, name accessors — UEVR's reflection metatable access |
| Math / String | Lua-native math, comparison, logic, vector and string helpers |

Every function carries a Lua expression template in its `metadata` field
(e.g. `uevr.api:find_uobject({0})` or `(({0}.Gamepad.wButtons & {1}) ~= 0)`),
so the registry is data-driven: extend it with your own game-specific
bindings by adding classes/functions with templates. `{0}`–`{n}` expand to
the node's data inputs in declaration order and `{target}` expands to the
Target pin. Pure functions with several outputs separate one template per
output with `|` (e.g. `{0}.x|{0}.y|{0}.z`).

## What the generator emits

- **Event nodes** → `uevr.sdk.callbacks.on_pre_engine_tick(function(Engine, DeltaSeconds) ... end)`
  with the event's outputs as callback arguments. Events with nothing wired
  to their exec pin are skipped.
- **Exec wires** → statements in order; **data wires** → expressions (pure
  nodes are inlined, impure results are captured in locals).
- **Blueprint variables** → script-scope `local` declarations with their
  default values.
- **Flow control** → native Lua: Branch → `if/else`, Sequence → statement
  order, For/While Loop → `for`/`while`, Do Once / Do N / Flip Flop / Gate →
  script-scope state locals (entering their `Reset`/`Open`/`Close`/`Toggle`
  exec inputs manipulates the state).
- **Property nodes** → direct UEVR metatable access (`pawn.bCanBeDamaged = false`).
- **Custom events** → `local function Name() ... end`.
- **Exec cycles** are detected and reported as comments instead of hanging
  the generator; data access to an impure node that never executed on the
  current chain degrades to `nil` with an explanatory comment.

Example output for the demo graph (View → UEVR Lua Editor in the example
program, which shows the script live in a syntax highlighted `TextEditor`
as you edit the graph):

```lua
-- haptic_jump.lua
-- generated by BlueprintEditor (UEVR Lua backend)

local RumbleAmplitude = 300.0
local GodMode = true

local doOnce12 = false

uevr.sdk.callbacks.on_xinput_get_state(function(Retval, UserIndex, State)
    if ((State.Gamepad.wButtons & 0x1000) ~= 0) then
        uevr.params.vr.trigger_haptic_vibration(0.0, 0.1, 1.0, RumbleAmplitude, uevr.params.vr.get_right_controller_index())
        uevr.api:get_local_pawn(0)["Jump"](uevr.api:get_local_pawn(0))
    end
end)

uevr.sdk.callbacks.on_pre_engine_tick(function(Engine, DeltaSeconds)
    if not doOnce12 then
        doOnce12 = true
        if GodMode then
            uevr.api:get_local_pawn(0).bCanBeDamaged = false
            print("Hello from UEVR")
        end
    end
end)
```

The generated scripts parse with Lua 5.4 (`luac -p`), which matches the Lua
runtime UEVR embeds; the bitwise `&` in the XInput helpers requires Lua 5.3+.

## Notes

- The generator is deliberately conservative: pure expressions are inlined
  where used (a pure node feeding three inputs is evaluated three times), so
  cache expensive lookups like `Find UObject` in a variable via a
  `Set Variable` node if it matters.
- The registry ships the commonly used core of UEVR's API, not all of it.
  Adding more is one fluent line per function.
